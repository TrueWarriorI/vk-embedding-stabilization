# Отчёт по проекту

## Задача

Цель проекта - стабилизировать эмбеддинги при смене версии рекомендательной модели. Качество проверялось по двум признакам. Скалярное произведение пользователя и объекта сохраняется внутри версии, а косинус между представлениями одной сущности растёт после выравнивания.

## Реализация

Матрица объектов обозначена `T`, матрица пользователей - `W`. Их общая размерность эмбеддинга - `d`. Каждый процесс хранит свой диапазон строк обеих матриц. Генератор использует фиксированный seed и умеет переходить к началу нужного диапазона, поэтому данные повторяются при изменении числа процессов.

1. Для каждой матрицы считаем локальный `R` через `torch.linalg.qr(mode="r")`. Процессы попарно объединяют факторы через `send` и `recv`. На каждом уровне выполняется QR для блока из двух треугольных факторов. При `p` процессах дерево имеет `log₂(p)` уровней. Для коротких блоков фактор дополняется нулевыми строками.
2. На главном процессе выполняем SVD матрицы `R_T @ R_W.T` размера `d × d`. По её сингулярным векторам и значениям вычисляем две матрицы преобразования и передаём их через `broadcast`. Полная матрица оценок `T @ W.T` нужна только в малом тесте и ноутбуке.
3. Для новой версии каждый процесс вычисляет часть матрицы `current_items.T @ reference_items` по одним и тем же объектам в преобразованных координатах. `reduce` суммирует вклады. SVD суммы даёт ортогональную матрицу Прокруста, которую через `broadcast` получают все процессы. Она применяется и к пользователям, и к объектам новой версии. Для ортогональной матрицы `O` произведение `(T' @ O) @ (W' @ O).T` равно `T' @ W'.T`.

Численный ранг определяется порогом `s > s_max × rtol`. Значение `rtol` по умолчанию равно `d × eps` для выбранного типа данных. Если отсечены малые ненулевые компоненты, оценки сохраняются приближённо. Выход сохраняет ширину `d`. Эталон - версия 0, сопоставление объектов основано на совпадении ID.

## Эксперименты

Окружение - Windows, Python 3.13.5, PyTorch 2.13.0+cu126, AMD Ryzen 5 7535HS, NVIDIA GeForce RTX 4060 Laptop GPU. В каждом процессе использовался один поток PyTorch на CPU.

Основной сценарий - 4096 пользователей, 3072 объекта, размерность 32, поворот 75°, seed 42 и `float64`. Отдельно проверен шум 0,15 с загрузкой эталона из файла. Косинус усредняется по совпадающим ID. Относительная ошибка - отношение L2-нормы разности оценок к L2-норме исходных оценок по выборке до 1024 пар на процесс.

| Сценарий | Устройство и процессы | Косинус пользователей | Косинус объектов | Ошибка оценок |
| --- | --- | ---: | ---: | ---: |
| Поворот | CPU × 1 | 0,2588 → 1,0000 | 0,2588 → 1,0000 | 2,15 × 10⁻¹⁵ |
| Поворот | CPU × 2 | 0,2588 → 1,0000 | 0,2588 → 1,0000 | 2,29 × 10⁻¹⁵ |
| Поворот | CPU × 4 | 0,2588 → 1,0000 | 0,2588 → 1,0000 | 2,19 × 10⁻¹⁵ |
| Поворот | CUDA × 1 | 0,2588 → 1,0000 | 0,2588 → 1,0000 | 1,55 × 10⁻¹⁵ |
| Поворот и шум | CPU × 2 | 0,2557 → 0,9889 | 0,2558 → 0,9890 | 2,30 × 10⁻¹⁵ |

Все 7 локальных тестов прошли. На малых данных проверены спектр относительно прямого SVD, совпадение `R.T @ R` с локальным QR, вырожденный ранг и полная матрица оценок. Дополнительно выполнены два запуска. На 4 CPU-процессах проверен набор из 3 пользователей и 7 объектов, в котором есть пустой блок. На одном GPU в `float32` при размерности 48 и шуме 0,1 ошибка составила 8,76 × 10⁻⁶, косинус после выравнивания - около 0,995.

## Замер времени

Для сравнения на CPU взяты 65 536 пользователей, 49 152 объекта и размерность 64. Время включает TSQR обеих матриц, малое SVD и рассылку преобразований. Для каждого шага записано максимальное время среди процессов. Генерация данных, запуск процессов, Прокруст и применение преобразований в эти значения не входят.

| Процессы | Эталон, мс | Новая версия, мс |
| ---: | ---: | ---: |
| 1 | 215,9 | 116,8 |
| 2 | 70,7 | 54,5 |
| 4 | 56,9 | 44,0 |

На этом наборе время QR и SVD уменьшилось с ростом числа процессов. Для каждой конфигурации выполнен один замер на одном компьютере. График строится по JSON в [ноутбуке](notebooks/demo.ipynb).

## Воспроизведение

```powershell
python -m stabilization demo --output results/cpu-1.json
python -m stabilization.launch --processes 2 demo --output results/cpu-2.json
python -m stabilization.launch --processes 4 demo --output results/cpu-4.json
python -m stabilization demo --device cuda --output results/cuda-1.json
python -m stabilization reference --reference runs/reference.pt --output results/reference.json
python -m stabilization.launch --processes 2 align --reference runs/reference.pt --noise 0.15 --output results/align-noise.json
python -m stabilization.launch --processes 4 demo --users 3 --items 7 --dim 8 --output results/short-shards.json
python -m stabilization demo --device cuda --dtype float32 --dim 48 --users 6144 --items 4096 --noise 0.1 --output results/cuda-f32.json
python -m stabilization demo --users 65536 --items 49152 --dim 64 --output results/scale-cpu-1.json
python -m stabilization.launch --processes 2 demo --users 65536 --items 49152 --dim 64 --output results/scale-cpu-2.json
python -m stabilization.launch --processes 4 demo --users 65536 --items 49152 --dim 64 --output results/scale-cpu-4.json
```
